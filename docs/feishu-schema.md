# 飞书多维表格 · 表结构说明

小秘书以飞书多维表格「任务」表为唯一主库。本文档描述表结构，供新建实例或恢复时对照建表。

## 建表方式

新实例可手动建表（对照下方字段清单），或用 lark-cli 脚本化创建。字段名必须与下表**逐字一致**——`task.py` 按字段名读写，改了字段名脚本就找不到列。

## 字段清单（21 个）

| 字段 | 类型 | 写入方 | 说明 |
|---|---|---|---|
| 任务ID | auto_number | 飞书自动 | 规则 `T-{创建日期}-{自增2位}`，如 `T-20261113-01`，不可手填 |
| 任务 | text | 用户 | 一句话说清做什么。要求一周后的自己能看懂 |
| 完成标准 | text | 用户（可空） | 可验收的一句话。允许留空，顺延过一次再补 |
| 状态 | select(单选) | 脚本 | 待做 / 进行中 / 卡住 / 已完成 / 已放弃 |
| 优先级 | select(单选) | 脚本 | 高 / 中 / 低，仅三档 |
| 所属项目 | text | 用户 | 项目名 |
| 父任务ID | text | 用户 | 子任务填父任务 ID；顶层任务留空 |
| 计划日 | datetime | 用户 | 打算哪天做。`list --today` 依据此字段 |
| 截止日 | datetime | 用户 | 硬性期限。超期由 `stats` 识别 |
| 预估分钟 | number | 用户 | 默认 25 |
| 实际分钟 | number | 用户 | 完成时填，用于校准估算偏差 |
| 顺延次数 | number | 脚本 | `block` 时 +1，完成时不清零 |
| 卡点 | text | 脚本 | 卡住原因原文 |
| 进展 | text | 脚本 | 上次停手时做到哪。跨日任务的续命字段 |
| 小结 | text | 脚本 | 完成结论，或"放弃：原因" |
| 产出链接 | text | 用户 | 产出文档路径或链接 |
| 开始时间 | datetime | 脚本 | `start` 时写入 |
| 完成时间 | datetime | 脚本 | `done` / `drop` 时写入 |
| 归档月 | text | 脚本 | 形如 `2026-11`，标记该条已进入归档期 |
| 创建时间 | created_at | 飞书自动 | |
| 更新时间 | updated_at | 飞书自动 | |

## select 选项枚举

- **状态**：待做、进行中、卡住、已完成、已放弃（顺序即生命周期顺序）
- **优先级**：高、中、低

## 建议视图

| 视图 | 类型 | 过滤条件 |
|---|---|---|
| 表格 | grid | 无（全量） |
| ① 今日 | grid | 计划日 = 今天，状态 ≠ 已完成/已放弃 |
| ② 进行中（看板） | kanban | 状态 = 进行中，按优先级分组 |
| ③ 时间安排（日历） | calendar | 状态 ≠ 已完成/已放弃，按计划日 |
| ④ 项目时间线（甘特） | gantt | 按项目分组，起止用计划日/截止日 |
| ⑤ 已完成归档 | grid | 状态 = 已完成 或 已放弃，按归档月分组 |

外加一个仪表盘：各状态计数卡、按项目分布、超期任务数、最近完成列表。

## 配置接入

表建好后，把 `base_token`（URL 里 `/base/` 后那段）和 `table_id`（以 `tbl` 开头）填进数据仓的 `config.json`，`task.py doctor` 验证通过即接入完成。
