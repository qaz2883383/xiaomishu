# 飞书多维表格 · 表结构说明（重建手册）

小秘书以飞书多维表格「任务」表为唯一主库。本文档的目标：**只拿数据仓（含本文件、config.json、task.py）就能在新飞书空间重建全部结构**。按顺序执行即可。

## 一、重建步骤（从零到接入）

1. **建多维表格**：飞书 → 云空间 → 新建 → 多维表格，命名「小秘书」。建好一个默认数据表，重命名为「任务」。
2. **建字段**：按下文「字段清单」逐个建。字段名必须**逐字一致**——task.py 按字段名读写，错一个字脚本就找不到列。任务ID 用自动编号类型，规则见清单。
3. **建视图**：按「视图清单」建 5 个视图，过滤条件照抄。
4. **建仪表盘**：按「仪表盘清单」加统计卡和图。
5. **取接入参数**：多维表格 URL 形如 `https://my.feishu.cn/base/<base_token>`；table_id 从 URL 或 API 取（以 `tbl` 开头）。
6. **填配置**：把 `base_token`、`table_id`、`base_url` 填进数据仓 `config.json`，跑 `python task.py doctor`，6 项全绿即接入完成。

> lark-cli 脚本化建表也可：`+field-create` 传字段 JSON 数组一次建全。但手动建表 20 分钟内可完成，且能顺便熟悉字段含义，推荐手动。

## 二、字段清单（22 个）

| 字段 | 类型 | 写入方 | 说明 |
|---|---|---|---|
| 任务ID | auto_number | 飞书自动 | 规则 `T-{创建日期}-{自增2位}`，如 `T-20261113-01`，不可手填 |
| 任务 | text | 用户 | 一句话说清做什么。要求一周后的自己能看懂 |
| 完成标准 | text | 用户（可空） | 可验收的一句话。允许留空，顺延过一次再补 |
| 状态 | select(单选) | 脚本 | 待做 / 进行中 / 卡住 / 已完成 / 已放弃 |
| 优先级 | select(单选) | 脚本 | 高 / 中 / 低，仅三档 |
| 分类 | select(单选) | 用户 | 学习 / 工作。决定完成时生成哪种报告、归档到哪个文件夹 |
| 所属项目 | text | 用户 | 项目名 |
| 父任务ID | text | 用户 | 子任务填父任务 ID；顶层任务留空 |
| 计划日 | datetime | 用户 | 打算哪天做。`list --today` 依据此字段 |
| 截止日 | datetime | 用户 | 硬性期限。超期由 `stats` 识别 |
| 预估分钟 | number | 用户 | 默认 25 |
| 实际分钟 | number | 用户 | 完成时填，用于校准估算偏差 |
| 顺延次数 | number | 脚本 | `block` 时 +1，完成时不清零 |
| 卡点 | text | 脚本 | 卡住原因原文 |
| 进展 | text | 脚本 | 上次停手时做到哪。跨日任务的续命字段 |
| 小结 | text | 脚本 | 完成结论，或"放弃：原因" |
| 产出链接 | text | 用户 | 产出文档路径或链接 |
| 开始时间 | datetime | 脚本 | `start` 时写入 |
| 完成时间 | datetime | 脚本 | `done` / `drop` 时写入 |
| 归档月 | text | 脚本 | 形如 `2026-11`，标记该条已进入归档期 |
| 创建时间 | created_at | 飞书自动 | |
| 更新时间 | updated_at | 飞书自动 | |

**字段类型补充说明**：

- 自动编号（任务ID）：飞书里选「自动编号」类型，格式设为「自定义」：文本段 `T-` + 日期段（创建日期，格式 YYYYMMDD）+ 固定文本 `-` + 自增数字（最小位数 2）。最终形如 `T-20261113-01`。
- datetime 字段（计划日/截止日/开始时间/完成时间）：开启「日期 + 时间」或仅日期均可，task.py 写入按毫秒时间戳。
- number 字段（预估分钟/实际分钟/顺延次数）：整数格式。

## 三、select 选项枚举

- **状态**：待做、进行中、卡住、已完成、已放弃（顺序即生命周期顺序）
- **优先级**：高、中、低
- **分类**：学习、工作

## 四、视图清单

| 视图 | 类型 | 过滤条件 | 说明 |
|---|---|---|---|
| 表格 | grid | 无（全量） | 默认视图，不动 |
| ① 今日 | grid | 计划日 = 今天，且 状态 ≠ 已完成、已放弃 | 每天早上看这个 |
| ② 进行中 | kanban | 状态 = 进行中，按优先级分组 | 手机上翻最顺 |
| ③ 时间安排 | calendar | 状态 ≠ 已完成、已放弃 | 按计划日显示 |
| ④ 项目时间线 | gantt | 无特殊过滤，按项目分组，起止用计划日/截止日 | 看项目节奏 |
| ⑤ 已完成归档 | grid | 状态 = 已完成 或 已放弃，按归档月分组 | 翻旧账入口 |

## 五、仪表盘清单（仪表盘名「任务统计」）

| 组件 | 类型 | 配置 |
|---|---|---|
| 各状态计数 | 指标卡 ×5 | 按状态分组计数：待做/进行中/卡住/已完成/已放弃 |
| 项目分布 | 柱状图 | 按所属项目分组，统计非终态任务数 |
| 超期任务数 | 指标卡 | 截止日 < 今天 且 状态 ∈ {待做, 进行中, 卡住} |
| 最近完成 | 表格组件 | 状态=已完成，按完成时间倒序，前 10 |

## 六、数据回灌（可选）

若数据仓 `data/tasks.json` 快照里有历史数据（count > 0），重建表后可用它回灌：逐条按字段清单把 tasks 数组写回新表（日期字段转毫秒时间戳，select 字段包成单元素数组）。误删单条记录的恢复走 `python task.py restore`（从 `data/graveyard.json` 回灌，预览→确认，输出新旧 ID 对照表并自动修复父任务引用）——整库重建则用 tasks.json 逐条 `add` 或由 agent 代写。

## 七、配置接入

表建好后，把 `base_token`（URL 里 `/base/` 后那段）和 `table_id`（以 `tbl` 开头）填进数据仓的 `config.json`，`task.py doctor` 验证通过即接入完成。
